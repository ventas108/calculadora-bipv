FASE 9 — Corrección de Error en Producción: Página 7 💰 Financiero

Contexto

Tras el despliegue exitoso descrito en la Adenda principal, se detectó un NameError en la Página 7 (Análisis Financiero — Ley 1715 de 2014) al intentar acceder a ella desde la app en producción.

Error detectado

NameError: name 'tipo_cambio' is not defined

Causa raíz: La variable tipo_cambio se utilizaba en la sección de cálculo CAPEX (línea ~120) pero se definía más abajo en la Sección 2 del formulario. Al ejecutarse el flujo lineal de Streamlit, Python intentaba usar la variable antes de que existiera en el scope.

PASO 9.1 — Diagnóstico del archivo en el servidor

Verificación de la posición de tipo_cambio en el archivo en producción:

(venv) root@bipv-colombia:/var/www/bipv/calculadora-bipv#
grep -n "tipo_cambio = float" bipv_python/pages/7_💰_Financiero.py

Resultado: tipo_cambio aparecía definida en la sección 2 del formulario (línea ~120) pero era referenciada antes en el bloque CAPEX → NameError confirmado.

PASO 9.2 — Aplicación del fix con nano

Se abrió el archivo con el editor nano en el servidor:

(venv) root@bipv-colombia:/var/www/bipv/calculadora-bipv#
nano bipv_python/pages/7_💰_Financiero.py

Fix aplicado — líneas 44-45 añadidas inmediatamente después del bloque de prerequisitos, ANTES de cualquier referencia a tipo_cambio:

ANTES (estructura incorrecta):
42:  n_pan = st.number_input("Número de módulos", ...)
43:
     ← tipo_cambio no existía aún;
       CAPEX la usaba y lanzaba NameError
DESPUÉS (estructura corregida):
42:  n_pan = st.number_input("Número de módulos", ...)
43:
44: # TRM disponible desde el inicio
45: tipo_cambio = float(
        st.session_state.get("tipo_cambio", 3400.0))

Guardado y cierre en nano:

Ctrl + O  →  [nano: "Save modified buffer?"]  →  Y  →  Enter  →  Ctrl + X

Verificación inmediata del fix:

(venv) root@bipv-colombia:/var/www/bipv/calculadora-bipv#
grep -n "tipo_cambio = float" bipv_python/pages/7_💰_Financiero.py

PASO 9.4 — Fallo en git push (token vencido) y diagnóstico

(venv) root@bipv-colombia:/var/www/bipv/calculadora-bipv#
git push origin main

ERROR obtenido:

remote: Invalid username or token.
Password authentication is not supported for Git operations.
fatal: Authentication failed for
  'https://github.com/ventas108/calculadora-bipv.git/'

Causa: El Personal Access Token (PAT) de GitHub embebido en la URL del remote había vencido. GitHub eliminó la autenticación por contraseña en agosto 2021; requiere PAT o clave SSH.

PASO 9.5 — Generación de nuevo PAT en GitHub

Procedimiento en el navegador:

  1. Ir a: https://github.com/settings/tokens/new
  2. Note: servidor-bipv
  3. Expiration: 90 days
  4. Scope: ✅ repo (acceso completo a repositorios privados)
  5. Clic "Generate token" → copiar el token generado.

⚠️ El token solo se muestra una vez al crearse. Guardarlo antes de cerrar la página.

NOTA DE SEGURIDAD — Buenas Prácticas con Tokens GitHub

Durante operaciones de emergencia en producción, los tokens pueden quedar expuestos en el historial de terminal. Medidas tras cada sesión:

  1. Ir a https://github.com/settings/tokens
  2. Revocar el token utilizado en la sesión.
  3. Generar un nuevo token solo cuando sea necesario.

Alternativa recomendada a largo plazo — autenticación SSH (sin tokens):

# En el servidor Digital Ocean:
ssh-keygen -t ed25519 -C "bipv-colombia-server"
cat ~/.ssh/id_ed25519.pub
# Agregar la clave en: GitHub → Settings → SSH and GPG keys → New SSH key

# Cambiar remote a SSH:
git remote set-url origin git@github.com:ventas108/calculadora-bipv.git

Con SSH, git push/pull no requiere token; la autenticación es por clave criptográfica almacenada en el servidor.
